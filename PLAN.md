1. Реализовать алгоритм роя без симулятора

Можно написать “чистую” Python-модель движения дронов в 2D/3D без Gazebo.

Суть: каждый дрон — это точка с координатами:

drone = {
    "id": 1,
    "x": 0,
    "y": 0,
    "z": 2,
    "vx": 0,
    "vy": 0,
    "vz": 0
}

И дальше ты моделируешь:

новая позиция = старая позиция + скорость * dt

Так можно реализовать:

полет к целевой точке;
leader–follower;
удержание формации;
избегание столкновений;
обход препятствий;
сбор метрик.

Это очень полезно, потому что потом этот же алгоритм можно перенести в ROS 2-ноду.

2. Сделать мини-симулятор на Python

Даже без Gazebo можно сделать простой симулятор через:

Python;
NumPy;
Matplotlib;
Pandas.

Минимальная цель: получить график траекторий роя.

Например:

drone_1: стартует из (0, 0)
drone_2: стартует из (-2, -2)
drone_3: стартует из (-2, 2)


цель: (20, 10)
препятствие: круг с центром (10, 5), радиус 2

На выходе:

траектория каждого дрона;
точки старта;
точка цели;
препятствие;
график минимального расстояния между дронами;
график ошибки формации.

Это уже можно вставлять в диплом как предварительное моделирование алгоритма управления.

3. Подготовить код ROS 2 без запуска симулятора

Даже без Gazebo можно писать структуру ROS 2-пакета.

Например:

drone_swarm_control/
├── drone_swarm_control/
│   ├── swarm_manager.py
│   ├── formation_controller.py
│   ├── collision_avoidance.py
│   ├── metrics_logger.py
│   └── utils.py
├── launch/
│   └── swarm_test.launch.py
├── config/
│   └── swarm_params.yaml
├── package.xml
├── setup.py
└── README.md

Что можно написать заранее:

formation_controller.py

Отвечает за то, где должен быть каждый дрон относительно лидера.

leader:     (0, 0, 2)
drone_2:    (-2, -2, 0)
drone_3:    (-2,  2, 0)
drone_4:    (-4, -4, 0)
drone_5:    (-4,  4, 0)
collision_avoidance.py

Считает отталкивание от соседей.

если расстояние между дронами < safe_distance:
    добавить отталкивающий вектор
metrics_logger.py

Сохраняет данные в CSV.

time, drone_id, x, y, z, target_x, target_y, target_z, formation_error, min_distance

Даже если ты не можешь запустить ROS 2, можно писать код так, чтобы потом быстро подключить его к топикам.

4. Написать unit-тесты для алгоритмов

Это очень практическая работа и хорошо смотрится в дипломе.

Можно тестировать без симулятора:

Тест 1

Проверить, что дрон движется к цели.

distance_to_goal после 100 шагов < distance_to_goal в начале
Тест 2

Проверить, что дроны не сталкиваются.

min_distance_between_drones >= safe_distance
Тест 3

Проверить, что формация сохраняется.

formation_error < заданного порога
Тест 4

Проверить, что препятствие вызывает отклонение траектории.

траектория не проходит через радиус препятствия

Это даст тебе сильную практическую часть: не просто “я запустил симулятор”, а я проверил корректность алгоритма.

5. Подготовить конфиги экспериментов

Без симулятора можно заранее создать YAML-файлы.

Например:

swarm:
  drones_count: 3
  safe_distance: 1.5
  formation_type: "v_shape"


leader:
  start_position: [0.0, 0.0, 2.0]
  goal_position: [20.0, 10.0, 2.0]


followers:
  - id: 2
    offset: [-2.0, -2.0, 0.0]
  - id: 3
    offset: [-2.0, 2.0, 0.0]


controller:
  k_goal: 0.8
  k_formation: 0.6
  k_avoidance: 1.2
  max_velocity: 2.0


simulation:
  dt: 0.1
  duration: 60.0

Потом этот же конфиг можно использовать и в Python-симуляторе, и в ROS 2.

8. Сделать псевдо-SLAM часть без тяжелой реализации

Полноценный SLAM можно не запускать. Но можно подготовить практическую модель:

Вариант A — известная карта

Ты задаешь препятствия вручную:

obstacle_1 = circle(center=(10, 5), radius=2)
obstacle_2 = circle(center=(15, 8), radius=1.5)

И рой использует эту карту для обхода.

Вариант B — имитация сенсора

Дрон “видит” препятствия только в радиусе, например 5 метров:

если расстояние до препятствия < sensor_range:
    учитывать препятствие
иначе:
    не учитывать

Это можно описать как упрощенную модель восприятия окружающей среды.

9. Сделать OpenCV-задачу без дрона

Например:

Простейший практический модуль:

камера видит красный круг

если круг слева — дрон поворачивает влево
если круг справа — вправо
если круг по центру — летит вперед
